# App API デザインガイドライン

`proto/app/` 配下の App API（モバイルアプリ向け）に固有のルール。共通ルールは `api-design.md` に従い、本ガイドはそれに追加・上書きする。

## 認証

- ユーザーに紐づくリソース（履修情報、個人カレンダー、ユーザー、FCM トークンなど）は認証情報からログイン中のユーザーを特定する。Request にユーザー ID を持たせない
- ログイン中のユーザー自身（`User`）はシングルトンとして扱い、`GetUser` / `UpdateUser` の Request に識別子を持たせない（[AIP-156](https://google.aip.dev/156)）

## リソース

- App API のリソースは表示用に非正規化してよい。関連リソースは ID ではなく message を埋め込む（例: `CancelledClass.subject`）
- 埋め込み用の message しか持たないリソース（`Room`、`Faculty`、`BusStop` など）も 1 ファイル 1 リソースとする
- 一覧と詳細で返す内容が異なるリソースは 1 つの message にまとめ、詳細でのみ設定するフィールドをコメントに明記する（例: `Subject.syllabus`）

## エラー

- `google.rpc.ErrorInfo` の `domain` は `app.dotto` とする

## AIP からの逸脱

`api-design.md` の「AIP からの逸脱」に加え、App API では以下を採る。

| 項目                         | AIP                                                                                         | App API                                                                                         | 理由                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| List の絞り込み              | `filter` 文字列で絞り込む（[AIP-132](https://google.aip.dev/132)、[AIP-160](https://google.aip.dev/160)） | 絞り込み条件を型付きのフィールドとして Request に並べる（フィールド番号 3 以降）                 | 既存 REST API との整合性。クライアントでの組み立てを容易にするため |
| List の必須フィールド        | AIP 規定外のフィールドを必須にしない（[AIP-132](https://google.aip.dev/132)）                | 取得範囲を決める条件（日付、開講時期など）は必須にしてよい                                       | 全件取得を防ぐため                                      |
