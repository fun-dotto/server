ワーキングツリーの変更を、意味のまとまり（セマンティックな単位）ごとに分割してコミットする。

## 手順

1. 差分全体を確認する。ステージ済み・未ステージ・未追跡のファイルをすべて対象にする。

   ```bash
   git status --short
   git diff
   git diff --staged
   ```

   未追跡ファイルは中身も読む。

2. 変更を意味のまとまりに分ける。
   - 1 コミットには、1 つの目的を持つ変更だけを入れる（機能追加・バグ修正・リファクタリング・設定変更・ドキュメントなどを混ぜない）
   - 生成コードは、生成元の変更と同じコミットに入れる
   - 各コミットの時点でビルドが通る順序にする
   - 1 ファイルの中に別の目的の変更が混在している場合は、`git add -p` で分ける
3. まとまりごとに、対象のファイルだけをステージしてコミットする。`git add -A` や `git add .` は使わない。
4. すべてコミットしたら、`git status` で変更が残っていないことと、`git log` で分割結果を確認する。

## コミットメッセージ

- 日本語で書く
- 1 行目: そのコミットでの変更内容を 1 文で簡潔に書く。末尾に句点は付けない
- 2 行目: 空行
- 3 行目以降: 変更点の詳細を箇条書きで書く
  - 各項目はできるだけ簡潔にする
  - 階層構造がわかるよう、補足や内訳はインデントしたサブ項目にする
  - 1 行目だけで十分な小さな変更では、箇条書きを省略してよい

例:

```text
シラバスのバージョン管理に対応

- syllabuses テーブルを変更
  - id を UUID にし、旧 id を lesson_id に改名
  - year・content_hash・fetched_at を追加
- 既存データを移行するマイグレーションを追加
- admin-api・app-api のハンドラを追従
```

HEREDOC で渡して、改行とインデントを保つ。

```bash
git commit -F - <<'MSG'
...
MSG
```
